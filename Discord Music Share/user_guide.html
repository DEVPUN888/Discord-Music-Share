Discord Music Presence

คู่มือการติดตั้งและใช้งานระบบแชร์เพลงจาก Spotify ไปยัง Discord Profile แบบอัตโนมัติ

⚠️ คำเตือนสำคัญ (Critical Warning)

การใช้งาน User Token (Self-bot) เพื่ออัปเดตสถานะเป็นการละเมิด Terms of Service (ToS) ของ Discord อย่างร้ายแรง ซึ่งอาจนำไปสู่การ ระงับบัญชีถาวร โปรดใช้ความระมัดระวังสูงสุดและไม่แนะนำให้ใช้กับบัญชีหลัก

🏗️ สถาปัตยกรรมระบบ

ระบบถูกออกแบบมาให้ทำงานแบบ Event-Driven Polling Loop โดยแยกส่วนการทำงาน (Modular Design) เพื่อความยืดหยุ่นในการบำรุงรักษา

Spotify Provider

เชื่อมต่อ Spotify Web API เพื่อดึงข้อมูลเพลงที่กำลังเล่นอยู่แบบ Real-time พร้อมระบบจัดการ Refresh Token

YouTube Provider

ค้นหา URL วิดีโอจาก YouTube โดยใช้ชื่อเพลงและศิลปิน พร้อมระบบ Caching เพื่อลดจำนวน Request

Discord Client

จัดการการส่ง HTTP PATCH request เพื่ออัปเดต Rich Presence ของผู้ใช้ผ่าน User Token

Coordinator & Rate Limiter

ควบคุมจังหวะการทำงาน (Polling) และเพิ่ม Jitter (การสุ่มเวลา) เพื่อให้พฤติกรรมเหมือนมนุษย์มากที่สุด

🚀 ขั้นตอนการติดตั้ง

1
เตรียมสภาพแวดล้อม

สร้าง Virtual Environment และติดตั้ง Library ที่จำเป็น:

pip install spotipy requests python-dotenv
2
ตั้งค่าความลับในไฟล์ .env

สร้างไฟล์ .env ใน Root directory และใส่ค่าดังนี้:

SPOTIPY_CLIENT_ID=your_spotify_client_id
SPOTIPY_CLIENT_SECRET=your_spotify_client_secret
SPOTIPY_REDIRECT_URI=http://localhost:8888/callback
YOUTUBE_API_KEY=your_youtube_api_key
DISCORD_TOKEN=your_discord_user_token
3
เริ่มการทำงาน

รันโปรแกรมผ่านคำสั่ง:

python main.py

🛠️ ข้อมูลทางเทคนิค (API Specs)

API Endpoint หลัก Auth Type Requirement
Discord /users/@me/settings User Token High Risk
Spotify /v1/me/player/currently-playing OAuth 2.0 user-read-currently-playing
YouTube /youtube/v3/search API Key Google Cloud Project

🛡️ มาตรการลดความเสี่ยง (Anti-Ban Strategy)

เพื่อให้บัญชีปลอดภัยขึ้น ระบบได้นำมาตรการต่อไปนี้มาใช้:

1. Human-like Behavior

  • Jitter: สุ่มเวลา Polling ไม่ให้คงที่ (เช่น 15-30 วินาที)
  • State Comparison: อัปเดต Presence เฉพาะเมื่อเพลงเปลี่ยนเท่านั้น เพื่อลดจำนวน Request

2. Identity Masking

  • User-Agent Mimicking: จำลอง Header ให้เหมือน Browser จริง
  • Rate Limiting: ปฏิบัติตาม HTTP 429 อย่างเคร่งครัด

⚖️ การวิเคราะห์ทางเลือก

หากคุณกังวลเรื่องความปลอดภัย นี่คือตารางเปรียบเทียบทางเลือกในการแสดงสถานะ:

หัวข้อ Self-bot (ปัจจุบัน) Official Bot Rich Presence SDK
ความปลอดภัย เสี่ยงสูงมาก ปลอดภัย ปลอดภัยที่สุด
ความสามารถ ทำได้ทุกอย่าง ตาม Permission แสดงสถานะเท่านั้น
ความเสถียร ต่ำ (พังง่าย) สูง สูงมาก
